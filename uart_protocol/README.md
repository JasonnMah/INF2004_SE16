# UART protocol — Stage 1 Pico W / RP2040

Latest reliability milestone (2026-10-19): see
[Stage 1 UART reliability results](tests/STAGE1_UART_RELIABILITY.md) for receiver
timeout/state fixes, regression evidence, and the next physical tests. The older
refactor results below describe their original milestone, not these later fixes.

This is the working single-Pico, dual-UART prototype, now separated into
protocol, Pico 1, Pico 2, and demo modules. The protocol, original mock bytes,
five test modes, and diagnostic messages are preserved.

Start with [REFACTOR_GUIDE.md](REFACTOR_GUIDE.md) for the module map, Member 1 RAM
buffer interface, build commands, and tests. See
[REFACTOR_TEST_RESULTS.md](REFACTOR_TEST_RESULTS.md) for current validation and
before/after metrics. Earlier reports and backups are preserved in the external
history archive described below.

## Wiring

| Simulated role | UART | TX | RX |
| --- | --- | --- | --- |
| Pico 2 / gateway | UART0 | GP0 | GP1 |
| Pico 1 / sensor | UART1 | GP4 | GP5 |

GP0 connects to GP5; GP4 connects to GP1. The serial monitor passively observes
GP0. UART settings remain 115200 baud, 8N1. Readable diagnostics and binary
frames share UART0, as in the original. USB stdio and SDK UART stdio remain
disabled because the demo owns both UARTs.

## Build and manually run Wokwi

Open this folder in VS Code with your existing Pico SDK 2.2.0 toolchain setup.
From its configured terminal:

```text
cmake -S . -B build -G Ninja -DPICO_BOARD=pico_w -DCMAKE_BUILD_TYPE=Debug -DPROTOCOL_TEST=0
cmake --build build --parallel 4
```

The target stays `uart_protocol` and emits ELF, BIN, and UF2. The unchanged
`wokwi.toml` uses `build/uart_protocol.uf2` and `build/uart_protocol.elf`.
Use **Wokwi: Start Simulator**, check the selected mode banner and recovery
messages, then confirm:

```text
[P2] TRANSFER_END validated
[P2] Retrieved compressed log matches Pico 1 data
[P2] CLEAR_LOG acknowledged
=== UART PROTOCOL FAILURE TEST COMPLETE ===
```

Repeat with `-DPROTOCOL_TEST=1`, `2`, `3`, and `4`, stopping and restarting Wokwi
after each build. Fresh configurations default to mode 4; existing caches keep
their selection. After folder cleanup, `build/` contains a clean mode 0 build. The VS Code
**Compile Project** task rebuilds that configured selection; change it with the
configure command above.

The user has manually verified all five refactored modes in VS Code + Wokwi.
Wokwi runtime was not run by the cleanup agent. Automated validation uses the
local RP2040 emulator and is reported separately.

## Automated checks

```text
npm ci --prefix tests
python tests/run_matrix.py
python tests/run_host_tests.py
```

The firmware matrix needs CMake, Ninja, Arm GCC, Python 3, Node.js, and SDK 2.2.0.
Host checks additionally need native GCC or a compatible compiler. See the guide
for path/selector details. Matrix output lives in `build/regression/results/`
and variants in `build/regression/mode-N/`; the active firmware directly in
`build/` is left alone. Host tests generate `build/host-tests/`.

The runner checks active source hashes before and after each full test run.
Golden UART captures came from fresh builds of the original, remain checksum
protected, and are never regenerated by normal tests.
